## Dependency notes

- The iPhone Mirroring benchmark can run immediately against the existing Mac
  stack and should inform mobile prompts, evaluations, and input semantics.
- The wire contract and conformance harness in Plan 001 must land before the
  Yutori SDK adapter, Android app, or MCP integration is treated as stable.
- The Android vertical slice must meet its evaluation gate before production
  relay work or a full iOS implementation begins.

## Findings considered and rejected

- **Build iPhone and Android in parallel:** rejected for the first milestone.
  Android exposes supported screenshot, UI-tree, gesture, text, and global
  action primitives to an Accessibility Service. iOS's supported arbitrary
  cross-app automation surface is XCTest/XCUIAutomation, which requires a
  development/test setup rather than a normal App Store companion app.
- **Wait for a native iPhone driver before testing iPhone tasks:** rejected.
  Apple's iPhone Mirroring already maps Mac clicks, swipes, scrolling, and
  keyboard input into a nearby locked iPhone, so the existing Mac CUA stack can
  measure n2's iPhone competence now. This is a local bridge, not a standalone
  phone driver.
- **Put native mobile projects in `yutori-mcp`:** rejected. This repository is
  a Python MCP package and should consume a released SDK/relay contract; Gradle
  and Xcode projects belong in a dedicated mobile-driver repository.
- **Reuse the current desktop tool set unchanged for production:** rejected.
  It includes desktop concepts and, in the latest dated surface, shell/file
  tools. A short-lived prototype may use the existing GUI-only batch tool set,
  but production needs a mobile-specific dated tool set.
